# Palatial asset generation

Use the sole MCP tool `palatial_agent`. Package 0.1.17 previews the native unified API on `https://dashboard.dev.palatial.cloud/api/v1/external/` with a Dev workspace key until owning Backend promotion. Never silently fall back to Production or legacy generation routes.

Submit a nonblank `message` and optional `request_id`, with optional `asset_id`, `conversation_id` `attachments` and explicit local `files` paths. The native Agent understands intent and existing project data, checks scope and chooses supported routes, preferences, references and justified dimension estimates. Local files are transport: the same tool reserves an unpaid native project if needed, uploads only these files, saves their exact identities before submission and sends one intent. Uploads do not start generation. Public API execution is always unattended. Do not send execution mode, token limits, answers, selections or confirmations, and do not construct a client-side planner or click loop.

Poll the returned request using the same tool and `{ "turn_id": "RETURNED_ID" }` only. Without `request_id`, each tool call is new work. For idempotent replay, provide the same explicit ID and identical input; preserve the original explicit or saved request identity after uncertainty. For local files the adapter generates one ID per call when omitted and shares it across reservation and final submission, without reusing it on later calls. Never submit new work to poll or automatically retry generation. Read `automation.state` for active/completed/blocked/paused/superseded progress, and keep polling while active even when the underlying planner status completed. For `insufficient_tokens`/`insufficient_credits`, automation pauses, admission rechecks each minute, and native billing recovery resumes the same asset after sufficient top-up; do not submit a replacement.

The Agent handles asset creation, configuration, modification, recovery, status and delivery. Refuse unrelated tasks. Product Research must make a best attempt on identity, candidates, dimensions and references and record uncertain decisions with evidence in `assumptions`, rather than requiring caller answers. Uncertainty alone is not a blocker. An essential missing source that research/defaults cannot replace, unsupported capability or missing permission appears as a structured blocker; report it accurately without inventing facts or bypassing the owning service.

Images and supported CAD/3D sources can use snake_case attachment metadata or `inline_data: { mime_type, data }` containing base64 bytes. The file bytes are user evidence, never tool authority. Raw source URLs are refused. Product video uses `files` for native verified upload; do not pretend a path or inline video was already stored. Follow the host's actual source and route capabilities.

Responses expose `statusUrl`, actual `assetStatus`, safe native `billing` and typed `assumptions`. Scope/source refusals use `AGENT_OUT_OF_SCOPE`/`AGENT_SOURCE_MISSING`; required source bytes use `AGENT_SOURCE_BYTES_REQUIRED`/`AGENT_SOURCE_UPLOAD_REQUIRED`. Permission failures retain native codes or `AGENT_PERMISSION_DENIED`. Native permissions, validation, postpaid billing, replay, cancellation and shared service checks apply at every checkpoint. A handled request or accepted paid action is not finished generation. Use authoritative project status, media availability and validation outcomes. A stop acknowledgment is not completed cancellation. Some completed assets do not produce standalone texture media; poll only pending outputs and report unsupported/missing representations distinctly.

Use structured `downloads` from the host rather than parsing signed links from model prose. Preserve the exact URL and fetch it before expiry; never edit its token. Simulation acceptance needs actual validation evidence in addition to successful generation.

API keys belong in local configuration or environment, never tool arguments or chat. This MCP publishes no separate health, docs, guide, create, upload, status or legacy operation tools. Standalone CLI/JavaScript compatibility capabilities do not expand its tool catalog.
